# 请假审批应用闭环任务清单与验收用例

本清单执行[技术方案](../architecture/leave-approval-delivery-design.md)，用于开发排期、代码评审和交付验收。编制日期为 2026-10-01，基线为 `framework / 7194f59`。任务状态按 [实施记录](../collaboration/2026-10-01-leave-approval-implementation.md) 更新，方案编写完成不代表开发任务完成。

## 1 使用方法

- P0 为 R1 必须完成；P1 为 R2；P2 为后续规划。优先级是本方案交付顺序，不替换仓库风险分级。
- 负责人列是角色归属，实际人员在 LA-001 填写；表中“依赖”是开始前必须满足的任务。
- 勾选要求：实现提交、必要自动化检查、相应验收用例和证据均完成。仅有页面、Mock、PR 或测试数量不能勾选。
- 实施中可将任务状态记为未开始、进行中、待验收、阻塞、完成，并填写阻塞原因和下一步；不可静默跳过。
- 当前已推进真实后端与页面接入，M0 Mock 对齐及部署证据仍待补齐；未勾选的任务仍须按各自完整验收要求完成。

## 2 里程碑

| 里程碑 | 范围 | 退出条件 |
| --- | --- | --- |
| M0 可复现基线 | LA-001 至 LA-009 | 范围、契约、运行环境与测试结构明确；旧前端关键回归通过 |
| M1 服务端业务闭环 | LA-010 至 LA-021 | 真实数据库完成提交、审批、驳回、撤回及版本固定；并发与隔离用例通过 |
| M2 用户操作闭环 | LA-022 至 LA-031 | 不同账号经页面完成业务；保存重开、错误恢复、消息和工作台可用 |
| M3 可试点交付 | LA-032 至 LA-036 | 容器部署、真实 E2E、备份恢复及证据报告通过 |
| R2 应用交付扩展 | LA-037 至 LA-042 | 可复制、配置、发布并使用另一个业务模板 |
| R3 后续增强 | LA-043 至 LA-045 | 按各自独立范围和验收进入研发 |

关键路径：M0 → M1 → M2 → M3。前端可在契约冻结后用 Mock 开发，M2 的真实验收必须等 M1 完成。R2、R3 不阻塞 R1，R1 不通过不得标记“生产验证”。

## 3 R1 任务

### M0 基线与契约

- [x] **LA-001 P0 冻结范围与实施记录**。负责人：技术负责人及产品；依赖：无。涉及：本方案、清单、实施记录。交付：实际负责人、后端资源确认、半日请假规则、审批人配置规则、排期估算、验收环境。验收：R1 边界和每项任务责任人明确；估算注明人员投入和假设，不承诺未验证工期。
- [x] **LA-002 P0 检查并保护仓库基线**。负责人：维护者；依赖：LA-001。涉及：Git 元数据、锁文件、工作区。交付：分支与 SHA、未提交工作备份、可恢复检查结果。验收：处理当前 `._*.idx` 引起的 Git 告警前先确认其为系统附属文件并备份；Git 读取和差异检查正常；不丢失用户内容，不按旧方案执行无关 reset 或分支清理。
- [ ] **LA-003 P0 统一运行环境**。负责人：工程维护者；依赖：LA-002。涉及：`.nvmrc`、`package.json`、Dockerfile、CI、README。交付：经兼容验证的 Node 24 LTS 与 npm 版本、固定依赖。验收：本地、CI、镜像环境一致，干净安装及旧项目 lint、typecheck、unit、build、E2E 通过；工具链升级单独提交并可回退。
- [ ] **LA-004 P0 增设 workspace 和测试边界**。负责人：工程维护者；依赖：LA-003。涉及：根 package、tsconfig、Vitest、新 packages 和 services。交付：单一根 lockfile、独立服务端和共享包构建。验收：前端 jsdom、后端 Node、集成测试不互相误收集；根 CI 覆盖全部 workspace。
- [ ] **LA-005 P0 冻结业务 DTO 和接口**。负责人：前后端；依赖：LA-004。涉及：`packages/contracts/`、`src/api/`。交付：请求响应、字段错误、401/403/404/409/422、幂等头、分页和 OpenAPI 文档。验收：API 与 Mock 使用同一契约；非法输入及额外的身份/状态字段被拒绝或明确忽略，不得生效。
- [ ] **LA-006 P0 冻结业务状态和发布模型**。负责人：后端及产品；依赖：LA-005。涉及：contracts、workflow-core、迁移设计。交付：申请/实例/任务状态表、发布快照规则、旧 version 的映射。验收：所有命令前置条件、终态和草稿发布过期行为明确，旧格式及未来格式有处理策略。
- [ ] **LA-007 P0 统一身份与权限类型**。负责人：前后端；依赖：LA-005。涉及：`config/index.ts`、`src/store/modules/user.ts`、`src/services/access.ts`、`src/mock/seed.ts`。交付：UserRole 与 MockRole 差异迁移、业务权限常量。验收：旧账号路由不回退；管理员、主管、员工和审计员按权限及资源关系判定。
- [ ] **LA-008 P0 建立稳定场景种子**。负责人：测试及后端；依赖：LA-006、LA-007。涉及：Mock seed、参考服务 seeds。交付：租户 A/B、每租户员工/主管/管理员/审计员、至少两个串行审批人、请假发布版和固定时钟场景。验收：账号身份独立、数据可重置、两端 fixture 对齐；不能只切换同一浏览器 role 值代替多人。
- [ ] **LA-009 P0 分离运行模式**。负责人：前后端及工程维护者；依赖：LA-005。涉及：`src/main.ts`、`src/mock/index.ts`、环境配置、运行时配置。交付：开发 Mock、持久化演示、试点模式。验收：生产前端不启用浏览器 Mock；API 失败不回退虚拟成功；测试可验证选中模式。

### M1 参考后端与流程运行

- [ ] **LA-010 P0 数据库迁移与约束**。负责人：后端；依赖：LA-006、LA-004。涉及：`services/reference-api/migrations/`。交付：技术方案全部 R1 表、租户组合关联、唯一约束、查询索引、迁移命令。验收：空库和上版测试库可迁移；跨租户关联、重复实例及重复节点任务被数据库拒绝。
- [ ] **LA-011 P0 认证和会话**。负责人：后端；依赖：LA-010、LA-007。涉及：auth 模块、现有 user API。交付：密码哈希、登录速率限制、可撤销会话、过期、登出、用户和菜单接口。验收：缺失/伪造/过期/已撤销 token 拒绝；示例口令仅用于演示。
- [ ] **LA-012 P0 服务端租户与资源授权**。负责人：后端；依赖：LA-011。涉及：tenant 模块、Repository 查询入口。交付：逐请求成员检查、租户过滤、对象权限及脱敏。验收：修改租户头、对象 ID、申请人或审批人字段均不能越权；停用身份立即影响后续请求；测试不依赖前端按钮隐藏。
- [ ] **LA-013 P0 表单与流程草稿持久化**。负责人：后端；依赖：LA-010、LA-012。涉及：application 模块、旧 form/workflow API。交付：真实列表、保存、读取、revision 检查。验收：重启后可读取，两个编辑者冲突返回 409；无效 Schema 不落库。
- [ ] **LA-014 P0 原子发布与活动版本切换**。负责人：后端；依赖：LA-013。涉及：ApplicationRelease、发布端点。交付：组合快照、发布校验、版本列表、回滚和审计。验收：表单与流程同时发布；任一步失败不产生半个发布版；老实例配置不变化；高级不支持节点不可发布。
- [ ] **LA-015 P0 串行流程领域核心**。负责人：后端；依赖：LA-006。涉及：`packages/workflow-core/`。交付：图校验、按边推进、抄送、结束、驳回、撤回纯函数。验收：改变节点数组顺序不改变执行路径；两个审批节点依次执行；环、断路、重复边和不支持节点拒绝；不执行表达式字符串。
- [ ] **LA-016 P0 请假草稿与服务端字段校验**。负责人：后端；依赖：LA-012、LA-014。涉及：leave 模块。交付：创建、保存、授权查询、半日时长计算、复制旧申请。验收：日期顺序、必填和发布版有效性复验；不能伪造用户、部门、时长；终态不能直接编辑。
- [ ] **LA-017 P0 原子提交与幂等**。负责人：后端；依赖：LA-015、LA-016。涉及：leave/workflow 命令服务、幂等表。交付：一个事务创建实例、首个待办、历史、审计及 Outbox。验收：故障回滚无孤立记录；重复点击及响应丢失重试仅创建一份；同 key 不同内容返回 409。
- [ ] **LA-018 P0 审批驳回撤回与并发**。负责人：后端；依赖：LA-017。涉及：workflow 命令服务。交付：固定锁顺序、状态和 revision 判断、后续节点创建、取消待办。验收：双击、两个独立请求审批同一任务、审批与撤回竞争均仅一次合法生效；终态一致、无残留 pending。
- [ ] **LA-019 P0 待办已办与历史查询**。负责人：后端；依赖：LA-018。涉及：workflow 查询服务。交付：分页、搜索、申请摘要、时间线和允许操作。验收：仅可查询授权范围；参与过审批的历史可读，跨租户资源不可见；顺序稳定。
- [ ] **LA-020 P0 Outbox 与站内通知**。负责人：后端；依赖：LA-017、LA-018。涉及：notification 模块和 worker。交付：事件领取、重试、去重、失败记录、已读及跳转数据。验收：worker 在写消息前后崩溃重启都不重复消息、不丢业务事件；消息故障不撤销审批结果。
- [ ] **LA-021 P0 服务端审计与可观测性**。负责人：后端；依赖：LA-012、LA-018、LA-020。涉及：audit 模块及日志。交付：操作主体、租户、对象、traceId、成功与拒绝事件。验收：前端不能伪造事实审计；不记录密码/token/完整事由；审计查询有权限，错误可追踪到服务日志。

### M2 页面与用户操作

- [ ] **LA-022 P0 租户全局上下文**。负责人：前端；依赖：LA-007、LA-009、LA-012。涉及：tenant store、请求客户端、菜单及路由缓存。交付：标签页独立租户、切换代次、取消请求、旧响应丢弃。验收：切换不串数据，失败保留原状态，旧响应不能覆盖新租户，未保存草稿有提示。
- [ ] **LA-023 P0 请假 API 与错误反馈**。负责人：前端；依赖：LA-005、LA-016。涉及：`src/api/leave.ts`、request-client。交付：类型化 API、字段 errors、冲突反馈、重试 key 生命周期。验收：保留既有 401 行为；422 定位字段，409 保留用户输入且不自动执行写操作。
- [ ] **LA-024 P0 请假表单运行页**。负责人：前端；依赖：LA-023、LA-013。涉及：leave 编辑页和 form-runtime。交付：新建、加载、保存、提交、离开保护和最后保存时间。验收：必填/日期/半日规则明确；保存失败内容仍在；重复操作禁用；正式提交走业务事务端点。
- [ ] **LA-025 P0 我的申请和申请详情**。负责人：前端；依赖：LA-019、LA-024。涉及：leave 列表详情。交付：状态筛选、分页、时间线、撤回、复制新申请。验收：终态只读；复制后旧历史保留；无数据、加载、错误和无权查看有明确反馈。
- [ ] **LA-026 P0 审批待办与已办**。负责人：前端；依赖：LA-018、LA-019、LA-023。涉及：`src/components/workflow-runtime/`、`src/views/workflowCenter/`。交付：查看申请快照、意见、通过、驳回、冲突刷新。验收：主管处理自己的任务；驳回意见必填；完成后待办、已办和详情同步。
- [ ] **LA-027 P0 工作台真实待办**。负责人：前端；依赖：LA-026。涉及：dashboard todo-panel 及刷新机制。交付：真实摘要、详情跳转和查看更多。验收：操作完成后数量变化；不存在只展示文字但不能打开的业务操作。
- [ ] **LA-028 P0 消息和审计页面联动**。负责人：前端；依赖：LA-020、LA-021、LA-025。涉及：message center、audit 页面。交付：结果通知、已读、授权跳转、关联审计查询。验收：撤权后旧消息不能绕过详情权限；前端遥测与服务端事实审计有区分。
- [ ] **LA-029 P0 请假应用发布面板**。负责人：前端；依赖：LA-014、LA-022。涉及：最小 application 发布页、现有设计器入口。交付：草稿选择、发布校验、版本列表、回滚。验收：编辑与运行入口清晰；发布失败明确定位问题；不把两次独立发布伪装成原子发布。
- [ ] **LA-030 P0 菜单权限及旧模块兼容**。负责人：前端；依赖：LA-025、LA-026、LA-029。涉及：路由、locale、权限常量、Mock 菜单。交付：业务用户入口与配置入口、旧状态迁移适配。验收：静态和服务端菜单均一致；直接 URL 访问受限；原表单预览与工作流演示不回退。
- [ ] **LA-031 P0 操作体验核验**。负责人：测试及前端；依赖：LA-027、LA-028、LA-030。涉及：R1 全部新增页面。交付：桌面 1440×900 与 1280×720、键盘 Tab、弹窗焦点、表单错误提示检查。验收：主动作可达、内容无阻挡、焦点可见；记录实际截图和问题修复，不据截图宣称全面无障碍合规。

## 4 R2 与后续任务

- [ ] **LA-037 P1 应用中心和模板复制**。负责人：前后端；依赖：LA-036。涉及：application 模块和管理页面。交付：应用列表、模板复制、配置和运行入口。验收：新应用有独立 ID、权限和版本，修改副本不影响原模板。
- [ ] **LA-038 P1 低代码动作执行器**。负责人：前端及后端；依赖：LA-037。涉及：low-code builder/runtime、动作注册表。交付：query、submit、navigate、openModal、refreshBlock。验收：逐项产生实际效果，权限拒绝和失败可恢复，目标区块明确，不执行任意脚本。
- [ ] **LA-039 P1 数据源与发布运行一致性**。负责人：前后端；依赖：LA-038。涉及：数据源登记、低代码 Schema、服务端查询适配。交付：白名单 sourceKey、字段映射和权限。验收：预览与发布版行为一致，任意 URL/越权数据源不可调用。
- [ ] **LA-040 P1 应用包导入导出**。负责人：前后端及测试；依赖：LA-039。涉及：Schema IO、迁移和引用映射。交付：包清单、版本、依赖、校验和迁移。验收：导出后在新租户导入，重新映射人员和数据源后可发布；不携带凭据和生产业务数据。
- [ ] **LA-041 P1 真实附件**。负责人：后端及前端；依赖：LA-036。涉及：文件资源 API、存储适配、申请表单。交付：受控上传下载、文件类型/大小校验、租户与申请绑定、存储生命周期。验收：真实文件上传下载一致，跨租户及撤权后访问拒绝，失败和孤立文件有清理策略；扫描要求在试点上线前明确。
- [ ] **LA-042 P1 第二业务模板复用**。负责人：产品及前后端；依赖：LA-040。涉及：业务模板及验收。交付：例如设备领用，明确是否需要附件并按需依赖 LA-041。验收：复用公共发布、权限、流程、审计，完成独立闭环；记录新增业务所需改动和工时，作为产品复用指标。
- [ ] **LA-043 P2 AI 辅助配置**。负责人：Agent 服务及前端；依赖：LA-040。交付：需求输入、模板选择、受约束生成、人工编辑、保存重开、导出。验收：非法 Schema 和越权引用拒绝；模型不直接发布，任务失败可恢复，费用和运行记录可追踪。
- [ ] **LA-044 P2 复杂流程和平台扩展立项**。负责人：架构及产品；依赖：LA-036。交付：会签、条件、转交、调度器、插件、大屏的独立需求及引擎适配评估。验收：每项有客户场景、运行语义、恢复方式和成本；不将这组任务视为一个可笼统勾选的实现包，进入实施时再拆分编号。
- [ ] **LA-045 P2 商业能力矩阵和组件库验证**。负责人：产品及 UI 平台；依赖：LA-036。交付：按模块标注演示/试点/生产验证/规划状态，按原治理流程进行 aheart-ui 小范围验证。验收：产品承诺绑定证据；组件库切换保持独立回归和回滚，不阻塞已交付业务。

## 5 R1 验收用例

| 编号 | 场景 | 预期结果 | 主要证据 |
| --- | --- | --- | --- |
| AC-01 | 员工申请，两名主管串行通过 | 第二个任务在第一个完成后出现，最后申请 approved、实例 completed | 多账号 E2E、数据库记录 |
| AC-02 | 主管填写意见驳回 | 申请与实例 rejected，无残留 pending，员工收到结果 | E2E、历史和通知 |
| AC-03 | 员工撤回进行中的申请 | 实例 withdrawn，待办 cancelled，再审批拒绝；可复制为新草稿 | E2E、API |
| AC-04 | 草稿保存后刷新、关闭重开、API 及数据库重启 | 内容、版本、身份、历史不丢失 | 操作记录、重启前后查询 |
| AC-05 | 两个编辑者保存同一 revision | 一个成功，另一个 409，保留输入不覆盖 | API 集成、页面反馈 |
| AC-06 | 提交响应丢失后同 key 重试 | 返回原结果，仅一个申请实例和首个任务 | 故障注入、数据库约束 |
| AC-07 | 相同 key 发送不同内容 | 409，不产生第二次业务效果 | API 集成 |
| AC-08 | 两个请求同时通过同一任务 | 一次状态迁移、一个后续任务、一组事实审计 | 真实数据库并发测试 |
| AC-09 | 审批与撤回同时发生 | 按锁顺序仅一个合法结果先提交，后者 409，无状态分裂 | 并发测试及最终记录 |
| AC-10 | 发布新版时有旧申请在途 | 旧申请按旧快照审批；旧草稿提交要求确认迁移；新申请用新版本 | API、E2E |
| AC-11 | 发布失败或回滚活动版 | 无半个发布版；新申请切版；历史不修改 | 故障注入、发布审计 |
| AC-12 | 提交包含环、断路、条件或并行节点的流程 | 发布拒绝且定位节点，不启动错误实例 | 领域和接口测试 |
| AC-13 | 租户 A 访问 B 的申请、任务、消息或审计 | 不泄露内容和资源存在性；写操作不生效 | API 负向测试、多账号 E2E |
| AC-14 | 切租户期间旧响应迟到，多标签页并用 | 新租户数据不被覆盖；另一个标签页上下文稳定 | 可控延迟 E2E |
| AC-15 | worker 在发送前后崩溃并重启 | 业务结果不回滚，通知最终一份；失败超过上限可查 | worker 集成、数据库 |
| AC-16 | token 过期、撤权、停用审批人、直接访问受限 URL | 下一次请求拒绝，表单有可恢复提示；无前端绕过 | API、E2E |
| AC-17 | 伪造申请人/部门/时长、日期倒置、缺少驳回意见 | 服务端复验并拒绝非法数据，前端定位错误 | API、表单测试 |
| AC-18 | 工作台和消息跳转并完成操作 | 打开同一授权详情；待办及状态更新，旧链接不能越权 | E2E、截图 |
| AC-19 | 新机器容器启动、试点模式探测 reset 和 Mock | 文档可复现；试点无重置路由及浏览器 Mock；持久卷保留 | 部署 smoke、构建检查 |
| AC-20 | 备份恢复到新实例、回退兼容镜像 | 申请、版本、任务、审计关联一致，能继续未完审批 | 恢复演练报告 |
