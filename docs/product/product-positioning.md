# 产品定位与版本分层

本文档对应 `T-601 产品定位与版本分层`。目标是把当前企业级中后台框架基线转成可对外说明、可演示、可报价和可交付的产品语言。

## 产品定位

AF-Ideal-Admin 是面向企业私有化交付、集团型管理系统、政企流程管理和内部数字化平台的中后台框架。它不是单一页面模板，而是一套包含权限、Mock-first 演示、表单设计器、流程设计器、低代码、大屏、报表、审计、主题和插件扩展的企业应用底座。

核心价值：

- 降低企业管理系统从零搭建成本。
- 让售前演示、需求确认和开发联调可以先基于 Mock-first 数据闭环推进。
- 为后续真实后端、私有化部署、二次开发和商业授权保留清晰边界。

## 目标客户

- 软件公司：需要快速交付企业后台、行业平台或内部管理系统。
- 集团企业：需要统一权限、组织、多租户、流程、报表和审计能力。
- 政企项目团队：需要可私有化部署、可审计、可扩展的管理平台底座。
- 低代码平台团队：需要把表单、流程、大屏、报表和插件能力组合成产品套件。

## 能力边界

- 开源版用于学习、评估和基础二开，不承诺完整商业交付材料。
- 专业版用于标准企业后台交付，重点提供演示数据包、部署模板、质量报告和产品化增强能力。
- 企业版用于私有化和行业定制，重点提供授权、租户隔离、行业模板、插件市场和后端适配支持。

## 商业化不包含项

- 不直接承诺替代客户现有真实后端业务系统。
- 不默认包含客户行业专属审批规则、报表口径和数据治理策略。
- 不默认包含生产环境运维托管。
- 不默认包含第三方短信、对象存储、地图、支付和统一身份平台账号费用。

## Mock-first 销售策略

Mock-first 是本产品的售前和交付优势。销售演示阶段先用稳定演示租户展示权限、流程、表单、低代码、大屏、报表和审计；客户确认业务价值后，再按 `docs/development/backend-integration.md` 把 Mock 契约映射到真实后端接口。

验收口径：

- 无后端也能完成完整产品演示。
- Mock 数据结构与真实 API 契约保持一致。
- 每个可销售模块都有演示账号、演示入口和预期结果。
- 接真实后端前先冻结接口契约和权限码。
