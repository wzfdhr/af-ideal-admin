# 应用定义包实施方案

状态：FP-019进行中，不以本文件代替真实导入运行。

格式v1包含应用说明及业务类型、表单/流程定义、平台和串行引擎依赖、规范引用键、待绑定人员槽位、明确脱敏清单和SHA256。应用/草稿/人员使用包内符号，不携带源租户、数据库对象ID、发布者、凭据、生产业务记录、会话、消息或真实附件。用户提供的定义标签保留；默认值在导出时明确去除并列明路径，避免把业务默认内容带入另一环境，不静默称作原样复制。

导出锁定源应用及对应活动快照；未发布应用要求两个草稿当前版本。导入验证大小、完整结构、摘要、依赖与格式，拒绝未知未来版本、任意脚本、不受控数据源和包外人员/表单引用。版本迁移必须有显式规则与数据保留依据；v1不通过改版本号伪装兼容。

人员在目标租户重绑，审批人必须当前具备审批权限，所有成员必须启用且未删除。导入在同事务创建独立应用及两个草稿、重映射表单引用并产生事实审计；幂等重试不重复创建。包不自动发布，发布继续验证人员和配置。包内引用不能绕过目标租户授权。

首批包承载真实已有表单和串行流程配置。低代码页面、材料、插件和受控数据源等仍需其模块实现后纳入版本化包，不能宣称一个表单/流程包已覆盖全产品包要求。设备领用需在另一真实租户导入、保存、发布并完成独立业务验证，再继续附件与部署门禁。

无需删除源应用或旧发布；回滚可归档新导入应用并保留历史及导入审计。包格式及依赖检查、恶意/非法输入、双租户人员引用、源版本冲突、导入事务失败与重试、浏览器导出/导入、重开及新部署运行均须有证据。正式源码/镜像版本化交付仍由FP-044/045验收。


格式v2扩展登记源槽位与form-contract v2、registered-sources v1依赖。导出把登记ID、内部source key和字段引用统一替换为包内source-N，去除选项/来源快照及版本；不携带源字典项或存储配置。目标租户显式选择自身已登记来源，服务器按当前权限、租户、类型、可用性校验，创建独立草稿及组合FK引用。发布时从目标来源重新读取并生成目标快照，不能沿用源数据。v1继续兼容，未来版本/依赖及不完整槽位拒绝。页面物料、插件、HTTP等后续包扩展和最终新部署导入验收仍未完成。
