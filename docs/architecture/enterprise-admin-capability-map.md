# 企业级中后台能力地图

本文档用于补充框架级能力边界。当前项目已经具备权限控制、基础菜单、登录鉴权、系统 CRUD、表单设计器、流程设计器、低代码页面搭建、数据大屏、报表中心、审计日志、可观测性、部署模板和常见页面模板。后续产品化重点是继续完善消息、多租户、文件、主题、插件化，以及把所有能力保持在 Mock-first 的可演示、可测试、可验收状态。

## 核心原则

- 所有框架能力都必须支持 Mock 虚拟数据演示。
- Mock 不是临时假数据，而是开发、联调、演示、测试的第一层契约。
- 每个企业能力必须同时具备：页面入口、API 契约、Mock 数据、权限码、基础测试、文档说明。
- 后端未完成时，前端仍应能通过 Mock 完成完整交互闭环。
- 后端完成后，Mock 数据结构必须能平滑映射到真实接口。

## Mock 虚拟数据平台

当前项目已有 Mock.js，但还处在接口散落和示例数据阶段。企业级框架需要把 Mock 作为一等能力建设。

### 必备能力

- 统一 Mock 开关：开发环境默认启用，生产构建默认关闭。
- Mock 数据分域管理：用户、权限、菜单、字典、流程、表单、大屏、报表、审计。
- Mock 接口契约与真实 API 契约一致。
- 支持分页、筛选、排序、详情、新增、编辑、删除、批量操作。
- 支持异常场景：401、403、404、500、业务错误、超时、空数据、弱网。
- 支持角色切换和租户切换，模拟不同权限下的菜单、按钮、数据范围。
- 支持开发者快速重置 Mock 数据。
- 支持 e2e 使用稳定 Mock 数据，避免测试依赖真实后端。

## 已有能力

### 权限控制

当前已有路由权限、按钮权限和登录守卫。后续需要升级为权限码模型，覆盖路由、菜单、按钮和数据范围。

### 表单设计器

当前已有拖拽表单设计能力。后续需要补充 schema 版本、运行时渲染器、远程数据源安全、导入导出、发布回滚和 Mock 表单提交。

## 缺少能力清单

### 1. 流程设计器

流程设计器适合审批流、工单流、业务办理流和状态机编排。

建议能力：

- 基于节点和连线的流程画布。
- 开始、审批、抄送、条件、并行、结束节点。
- 节点属性配置面板。
- 表单绑定：流程节点可绑定表单设计器 schema。
- 条件表达式使用安全配置，不执行任意脚本。
- 流程预览、校验、发布、停用、版本管理。
- 流程实例模拟：发起、审批、驳回、转交、撤回、结束。
- Mock 流程数据：流程定义、流程实例、待办、已办、审批记录。

推荐技术：

- 现有项目已引入 AntV X6，可优先复用为流程画布基础。

### 2. 低代码页面搭建

低代码不是替代所有开发，而是让常见管理页面可以配置生成。

建议能力：

- 页面 schema：布局、区块、表格、表单、图表、操作按钮。
- 物料市场：ProTable、ProForm、ChartCard、StatisticCard、WorkflowPanel。
- 数据源配置：REST API、Mock API、静态 JSON。
- 事件配置：查询、提交、跳转、打开弹窗、刷新区块。
- 权限配置：页面权限、区块权限、按钮权限。
- 预览、保存、发布、回滚。
- 生成代码或运行时渲染两种模式。
- Mock 页面数据，支持无后端演示。

### 3. 大屏设计与可视化

当前项目已有 ECharts 示例，但缺少面向大屏的设计、配置和数据模拟体系。

建议能力：

- 大屏画布：1920x1080 基准，支持自适应缩放。
- 图表组件：折线、柱状、饼图、地图、排行、指标卡、滚动表格。
- 大屏组件拖拽、缩放、层级、对齐、吸附。
- 数据源绑定：Mock 数据、REST 数据、轮询刷新。
- 主题配置：暗色主题、行业主题、企业品牌色。
- 预览和全屏播放。
- Mock 实时数据：指标波动、地图点位、排行变化、告警滚动。

### 4. 报表中心

报表中心面向经营分析、数据导出和管理驾驶舱。

建议能力：

- 报表列表、报表详情、查询条件、导出。
- 固定报表和自定义报表。
- 指标口径说明。
- 定时刷新和导出任务。
- 权限控制到报表和字段。
- Mock 报表数据：趋势、分布、明细、空数据和异常数据。

### 5. 工作台与消息中心

企业中后台通常需要统一工作入口。

建议能力：

- 我的待办、我的申请、我的审批、系统公告、快捷入口。
- 消息通知：站内信、公告、待办、告警。
- 消息已读、批量已读、跳转业务详情。
- Mock 消息流和待办数据。

### 6. 审计日志与操作日志

建议能力：

- 登录日志。
- 操作日志。
- 权限变更日志。
- 数据导出日志。
- 异常日志。
- 支持按用户、时间、模块、结果筛选。
- Mock 正常日志、失败日志、敏感操作日志。

### 7. 多租户与组织架构

建议能力：

- 租户切换。
- 组织树。
- 部门、岗位、用户关系。
- 数据权限范围：全部、部门、本部门及下级、本人。
- Mock 多租户、多部门、多角色数据。

### 8. 文件与资源管理

建议能力：

- 文件上传、下载、预览。
- 图片、PDF、Excel、Word 常见资源预览入口。
- 上传大小、类型和权限控制。
- Mock 上传成功、失败、超限、格式错误。

### 9. 国际化与主题中心

建议能力：

- 菜单、路由、表单、字典、错误提示国际化。
- 主题色、暗色模式、紧凑模式。
- 品牌配置：Logo、标题、登录页背景。
- Mock 不同租户品牌配置。

### 10. 插件化与扩展机制

建议能力：

- 模块注册。
- 路由注册。
- 菜单注册。
- 权限注册。
- Mock 注册。
- 物料注册。
- 避免核心框架和业务模块强耦合。

## 推荐建设顺序

1. Mock 虚拟数据平台。
2. 权限码和服务端菜单。
3. 可替换 UI 底座边界：Arco adapter 当前交付，`aheart-ui` adapter 并行验证。
4. ProTable、ProForm、字典服务。
5. 表单设计器生产化。
6. 流程设计器 MVP。
7. 大屏可视化 MVP。
8. 低代码页面搭建 MVP。
9. 报表中心、审计日志、消息中心。
10. 多租户、组织架构、数据权限。
11. 插件化和框架生态。

## 缺失能力路线图

### 近期增强能力

- 消息中心：已完成站内信、公告、待办、告警和已读状态 MVP，后续优先补消息跳转联动、消息订阅和 WebSocket 推送。
- 多租户：建设租户切换、组织树、部门岗位关系和数据权限范围。
- 文件与资源管理：建设上传、下载、预览、大小类型限制和资源权限控制。

### 中期产品化能力

- 主题中心：建设租户品牌、Logo、标题、主题色、暗色模式、紧凑模式和 `aheart-ui` 主题变量验证。
- 数据权限：在现有权限码模型上补充本人、本部门、本部门及下级、全部数据范围。
- 消息、审计、报表联动：报表导出、流程审批、权限变更和异常告警都应产生消息或审计记录。

### 长期生态能力

- 插件化：定义插件 manifest、路由注册、菜单注册、权限注册、Mock 注册、物料注册和启停生命周期。
- 组件生态：围绕 Pro 组件、UI adapter 和 `aheart-ui` 建立业务组件市场。
- 模块市场：把流程、低代码、大屏、报表、审计等能力沉淀成可装配模块。

## 企业级验收补充

- 每个新增能力都必须提供 Mock API。
- 每个新增能力都必须有至少一个完整演示页面。
- 每个新增能力都必须有权限码设计。
- 每个新增能力都必须有空数据、异常数据、无权限数据场景。
- 每个新增能力都必须写入开发文档。
- 每个新增能力都必须能在无后端环境下完成演示、测试和验收。
- 新增业务页面必须优先依赖 Pro 组件和 UI adapter 边界，避免直接绑定底层 UI 组件库。
