# 真实文件与附件实施方案

状态：FP-020/021进行中。现有元数据Mock不能作为文件交付证据。

首批使用本地持久化对象存储驱动，根目录通过FILE_STORAGE_DIR配置，服务端UUID和SHA256生成对象键，用户文件名不参与路径。接口分为上传会话、真实字节分片、校验完成、耐久扫描、授权内容读取和删除/清理。单文件20MiB，分片1MiB，声明类型/扩展名/大小/摘要必须与实际字节匹配。后续存储替换须沿同一驱动与验收，不把本地验证写成S3或客户部署成功。

上传身份、租户和业务关联由后端校验。关联文件只能由草稿所有者上传；上传完成及扫描就绪前，业务提交不能将未准备附件带入流程。已提交业务不允许悄悄增删附件。文件下载/预览除功能权限外，每次按当前会话和业务可见范围重新授权；不发绕过撤权的永久公开URL。无业务关联的文件仅上传者可见。

病毒扫描接入ClamAV INSTREAM，扫描服务不可用或结果错误时保持隔离，绝不默认clean。扫描任务使用数据库状态、租约、有限重试和版本，进程退出后可接续。感染文件不可下载。扫描引擎及病毒库的真实版本须记录，测试替身不作为正式扫描验收。

元数据与实际文件写入跨系统，不能声称单数据库事务覆盖文件系统。对象写入使用内容寻址及原子独占创建；分片和上传记录保存同版本/幂等边界。数据库失败留下的未引用对象由有年龄阈值的清理处理；不能在写入仍进行时删文件。未完成上传过期、失败重试、删除和孤立文件清理要分别验证。删除已完成业务关联要拒绝，业务历史和事实审计保留。

下载使用二进制响应，浏览器先经带认证的请求读取再生成本地预览/下载，不保存服务器公开地址。文本、图片和PDF可预览，其他文件仅下载；禁止把HTML、SVG或脚本当作可执行预览。响应设置nosniff、安全内容类型和处置头。

首批必须具备真实数据库/文件字节一致性、双租户/多账号、大小/类型/摘要非法输入、分片重试、扫描失败/感染、服务重启、清理及权限撤销证据，再完成浏览器和全产品部署备份。原R1数据、卷和包保持独立；新增文件目录必须随备份完整恢复，回退不得让旧元数据上传入口假冒真实文件能力。

ClamAV协议依据：[官方协议说明](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)。守护进程TCP接口只绑定本机或受控内部网络，不公开暴露。
