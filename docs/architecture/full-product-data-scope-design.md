# 成员数据范围首批实施

状态：FP-006 进行中。此实现覆盖租户成员接口，不能作为业务记录、附件、报表、审计或整个产品数据权限完成的证明。

## 数据模型与授权语义

008 增量迁移建立 role_member_scopes 和 role_scope_departments，以租户与角色、部门组合外键隔离数据。现有角色迁移为原有租户内全部范围；新建角色默认本人及账号、姓名、部门、状态四个字段。008 已应用到独立开发演示库，后续改变数据库定义必须追加迁移。

成员范围支持本人、指定部门、部门及下级、本租户全部。未指定部门时使用访问者当前所属部门。all 与兼容 tenant 都不跨租户。直接功能授权保留租户内全部范围；因此范围受限的管理者不能通过直接授权授予自己无法覆盖的范围。

SQL af_member_scope_visible 在列表、详情、更新、删除、密码重置、角色分配和岗位成员目标查询执行。af_member_field_visible 要求同一角色同时覆盖目标行与字段，不允许把一个角色的全部行与另一个角色的本人联系方式拼接成全部联系方式。查看原始联系方式仍需要功能权限。隐藏字段不能通过筛选条件恢复；成员修改回执只返回标识、版本和必要状态，不缓存姓名或联系方式。

角色分配、直接授权、已绑定角色权限修改和范围配置，都检查操作者能够授予的范围与字段。检查使用变更前的策略；禁止把当前角色修改后的更宽范围作为授权依据。新建未分配成员需要全部成员创建范围及输入字段权限，不能以本人创建权限生成范围外账户。检查保守要求一个已有策略完整覆盖候选策略，暂不支持计算多个局部部门策略的任意并集覆盖。

租户治理写入使用现有租户排他锁、版本与幂等控制。范围修改、角色和成员版本更新、租户权限版本及事实审计在同一事务提交。最后一位拥有全部成员查询与数据范围配置能力的治理者不能被限制为本人或被撤权、停用；失败回滚全部版本和规则修改。

## 真实页面与 API

- GET /api/permissions/data-scopes：分页规则。
- PUT /api/permissions/data-scopes/:id：严格规则、expectedRevision 与 Idempotency-Key。
- GET /api/permissions/data-scopes/:id/members：当前租户已绑定的启用访问者。
- POST /api/permissions/data-scopes/preview：仅预览已保存规则及真实已绑定成员，最多100行，不返回隐藏行数据。
- /permissions/backend/data-scope：真实配置、保存重开、授权字段与预览页面。reference 模式使用真实 API；旧 Mock 页面仅维持开发演示，未实现新范围生命周期。

配置与预览目前要求当前租户全部成员查询能力，拒绝范围受限的配置者自行扩权。未来支持委派范围治理时，必须继续复用候选范围检查，不能取消这一边界。

## 回滚

原 R1 镜像、数据库卷及版本化包保持独立。新增表和 SQL 函数不删除历史业务数据。回退前应备份新规则、角色与成员授权；旧服务不理解范围约束，因此不得直接把受限生产授权交给旧服务，否则范围会扩大。需要撤销这些成员权限或使用继续执行范围检查的兼容版本，并完成新实例恢复验收。当前未宣称这条生产回退路径已经验收。

原始联系方式另受 read-contacts 自身的目标行及字段策略约束。只有本人联系方式权限的角色，不能借另一个全租户成员查询角色读取或按原始电话筛选他人；无该目标授权时返回脱敏值，写回执仍不带联系方式。已添加真实失败回归与修复记录。
