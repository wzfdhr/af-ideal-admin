# 结构化表单校验与联动

FP-011/012进行中。表单v2增加明确的validation及behavior，不执行JS、用户表达式或任意正则。v1快照保持原义，v2的未知规则/字段/未来版本拒绝，不静默过滤错误规则。

validation支持有界最小文本长度、命名格式email/https-url/phone及同类型字段的相等、数字/日期先后比较；数值类型和范围沿用已有整数/金额契约。日期要验证真实日历。behavior支持由一个普通字段与受控字面值相等/不等决定显示或条件必填。引用字段必须存在，禁止引用自身或受联动控制字段，防止循环和级联不确定性。

后端确定联动状态；隐藏字段不接受非空新输入，也不作为必填。保存允许未填写的草稿，已填写字段仍执行校验；提交、预览执行完整必填及跨字段校验。客户端使用同一共享条件及规则函数显示/清理隐藏值并反馈，不能替代后端验证。清理只针对当前编辑状态，历史业务只读展示不改写存储内容。

设计器提供结构化配置，字段改变可立即预览，保存重开/发布/业务提交读取一致。当前先支持一次条件和已登记比较，不用“可填任意代码”表单假装支持复杂逻辑；多级联动、HTTP受控参数源、更多控件和版本对比仍须继续完成原规划。新规则随定义包保留，不携带业务值。

验收包含真实日历、长度/格式、条件必填、隐藏值注入、未知/自引用/循环/错类型/脚本拒绝、客户端与服务端一致、错误恢复、双租户及旧R1回归。变更不增加数据库迁移，发布仍固定不可变快照；回退应用保留v2数据，新规则暂不能由不支持的旧二进制解读，不伪称向下兼容。

驱动字段暂限可编辑文本/整数输入及单选；文本匹配字面值必须为字符串，整数匹配字面值必须为非负安全整数，并统一规范化匹配（例如草稿的02和存储的2）。不使用只读默认值作为驱动，也不允许比较引用受联动控制的目标。v2的布尔状态/有界最大长度及按日日期模式严格校验。固定请假模板的专用后端不消费这些新增规则，因此保存/发布时明确拒绝，通用设备领用模板用于本批真实验证。
