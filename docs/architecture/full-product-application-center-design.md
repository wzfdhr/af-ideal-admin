# 应用中心首批实施

状态：FP-009 进行中。首批以真实应用创建、独立复制、配置、发布、请假运行、归档和恢复形成纵向路径；通用业务记录和第二个业务模板仍属于必须继续的 FP-010/011，不能以复制请假模板代替。

## 模型与事务

009 增量迁移给 applications 增加说明、业务类型、归档状态和默认表单/流程草稿引用。引用使用租户组合外键。已有 R1 为 leave 类型，保留历史发布和业务记录；空白应用为 generic 类型。009 已应用到专属开发演示库，后续数据库变化必须追加迁移。

创建和复制分别生成新的应用、表单草稿及流程草稿 ID，初始应用版本为1，尚未发布。内部业务字段键保留，避免破坏运行时字段契约；流程节点 formId 引用重映射到新表单草稿。发布后每个应用独立计算发布版本，不复用原发布ID，不复制业务记录、历史、消息、凭据或会话。

已发布源应用复制当前活动不可变快照；未发布源应用复制指定版本的两个草稿。源应用版本和草稿版本必须匹配，读取和复制在事务锁内完成。源或草稿已变更返回冲突，未发布源缺少草稿版本返回明确校验错误。列表提供草稿版本元数据，具有目录/复制权限但没有配置权限的操作者无需读取全部草稿内容也能提交受控复制。

元数据维护只能改名称与说明，标识和业务类型不可变。标识为租户内唯一，归档后不回收标识。状态维护、元数据、创建及复制都要求命令幂等标识；更新和状态要求 expectedRevision。应用、草稿及事实审计同事务提交；唯一约束冲突映射为明确409。

## 发布与运行

新应用发布只允许自身默认的两个可变草稿。其他应用拥有的草稿不能直接借给 R1 发布；需要复制配置后再发布。已发布快照继续受数据库不可变触发器保护。

发布使用现有配置校验、真实人员校验、版本锁、内容摘要与审计。leave 应用继续验证固定请假字段，并通过既有请假/审批引擎运行；generic 目前可保存配置，但正式通用业务运行时仍待 FP-010，不提供假运行按钮。空白流程必须由用户补足真实审批配置后才能发布。

归档不删发布、不改变历史实例快照或已分配审批。归档应用不能创建、编辑提交新业务、发布或切换活动版本；历史审批仍能完成。恢复是受权限、版本和幂等保护的显式状态操作，不偷偷重发版本。

## 接口与页面

- GET /api/application-center 及 /:id：权限内的本租户目录和元数据。
- POST /api/application-center：空白或当前租户请假模板创建。
- POST /api/application-center/:id/copy：受版本控制的独立复制。
- PATCH /api/application-center/:id：名称和说明。
- PUT /api/application-center/:id/state：归档/恢复。
- /applications/center：真实目录、创建、查询、复制、应用信息、配置、归档、恢复和已发布请假应用运行。
- /applications/:id/configuration：复用现有两个设计器，按当前应用读取独立草稿；跨应用切换检查未保存修改，丢弃延迟旧应用响应。

管理权限是 application:list/create/copy/archive 和已有 configure/publish/rollback。服务端校验所有命令与对象租户。旧运行入口读取新应用未发布或 generic 配置时，要求目录/配置权限；认证读取事务刷新成员权限，不能以旧登录权限读取已撤权配置。基础 R1 运行入口保持兼容。

新权限只由显式隔离演示初始化授给演示管理员；旧生产授权不自动升级为新权限。新平台治理初始化按当时已启用目录授予明确代码，不使用通配符。实际生产升级授权仍须随最终交付方案执行。
