# 表单受控数据源实施方案

FP-011进行中，登记和预览不代表表单发布/提交绑定完成。保留R1固定选项和v1包，不把用户填写URL当作服务端授权。

先建立独立、租户自有的form_data_sources登记表。第一类连接既有真实字典，通过tenant+dictionary组合FK绑定；登记、修改、启停共用revision与幂等键，事实审计同事务。数据源code固定，名称/说明/启停可维护。查询源需要独立使用权限以及底层字典的读取权限，不能借登记扩大数据访问。

查询只返回受控label/value，不携带个人联系字段。字典停用、删除或源停用明确失败，空字典才返回成功空数组。响应最多200项，事务内设置查询超时；浏览器使用认证request客户端和租户代次保护，不从配置URL调用裸axios。禁止用户自定义脚本、任意SQL、未知响应映射或请求头。

设计器的数据源管理先提供真实登记、重开、预览、版本冲突和启停反馈。随后扩展明确版本的表单契约，使选项绑定引用登记ID；发布时验证当前租户/权限/可用性，记录源版本与选择口径。旧业务仍引用自己的不可变表单快照。服务端保存和提交必须执行选项有效性校验，不能只靠浏览器下拉列表。

远程HTTP登记是后续同一任务的独立子项：来源由部署者白名单配置，限定方法/路径/字段映射/响应大小，禁止自动重定向、任意目标及用户传入凭据；补实际超时/错误恢复和受控联动。这一能力不能用字典查询替代，尚未实施的动作不显示为可用。

依赖引用会纳入应用包重绑规则，不能导出原租户数据源/字典ID。数据源绑定、复杂校验、联动、格式迁移及备份恢复没有证据前FP-011/012/019均保持未完成。

绑定使用表单格式v2；v1固定字段及历史快照继续读取，不把流程格式一并升级。v2字段只引用包内source key，登记ID只由后端按当前租户验证。草稿禁止携带伪造选项快照；发布时后端读取来源并把选项及源/字典版本固定在发布快照。选择值按既有表单字符串契约规范化，若底层类型不同但转为字符串后重复，明确拒绝，不静默覆盖。修改字典项需重新发布才能改变该版本的选择集合。

业务保存/提交校验发布的选项集合，并重新检查来源、字典启停、当前使用权限及选项仍处于启用状态；新增加的值必须重新发布后才能使用，已停用或移除的值立即不能用于新的保存/提交；历史业务继续读取其原快照。数据库保存草稿/发布与登记的组合FK，避免JSON引用越过租户。选择集合固定与来源可用性是两个独立规则。应用包扩展必须重绑来源且重建目标快照，原v1包不能悄悄携带新增来源引用。

014仅新增登记表和权限，回退可以保留表；已被发布引用的数据源不得物理删除。专项验收覆盖跨租户FK和读取、底层权限拒绝、禁用源与字典、版本冲突、同key一次、失败回滚、设计器管理及真实数据预览。最终还需服务重启、全新部署/备份和回退证据。
