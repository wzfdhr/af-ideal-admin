# 流程转交与异常恢复实施边界

FP-015进行中，已实施当前参考后端与页面增量，正式部署/恢复门禁仍开放。接续v1串行、v2条件和v3并行/会签；不改旧release、不以恢复操作绕过审批。FP-016超时调度保持独立任务。

1. 区分本人待办转交和管理者异常恢复权限。目标必须为同租户、可见范围内、当前启用且具备审批权限的成员；候选仅返回必要身份与资格，后端不依赖选择器过滤。目标不得是申请人，也不得在同一会签活动占据第二票位。
2. 转交保留task.id及原签署票位，更新分配人/revision，追加不可变原分配/新分配/操作人/原因/版本事实；不通过复制任务增加会签票数。旧人立即不能处理，新人实际收到待办。转交前后的历史/详情阅读资格须由后端显式判断，撤权不能靠历史绕过。
3. 任务、活动和实例必须仍在可处理状态，预期任务revision和稳定命令key必需。与审批、撤回及其他转交竞争时沿业务→实例→任务/活动一致锁序，只有一个效果；审计、通知及assignment事实同事务，原key可安全恢复。
4. 异常恢复列出真实停用/撤权分配人及无法继续的实际下一节点，不伪造可处理待办。允许获授权管理者恢复现有票位，或对实际阻塞的下一节点设置实例级分配覆盖；记录原因/原配置/新分配/作用范围，发布快照保持不变。不得修改未激活的任意分支或已处理投票。
5. 当前下一人失效时，审批命令整体回滚并保留原任务；恢复完成后原处理人重新提交实际决策，再产生新任务。会签途中恢复也不改变阈值或已签票。恢复与重新失效/撤权竞争须重验目标当前资格，不自动跳过该节点。
6. 事实保留和任务引用使用复合租户/实例FK及新迁移，001至017校验和保留；修改中的应用草稿、源租户引用、浏览器状态或当前活动版本不能替代原实例配置。实际API进程替换后仍能查询assignment与恢复覆盖并继续。
7. UI提供转交候选/原因、当前异常及恢复结果/历史，多任务必须明确操作哪一项。真实多账号、双租户完成交接后审批，旧人拒绝、新人通过、同会签重复票位拒绝、自审/越权/停用/撤权/已结束拒绝、错误输入保留、幂等/并发/故障恢复及重启证据。
8. 保留完整R1/条件/并行/会签门禁、对应提交远端CI及证据。新部署、备份恢复、兼容回退和正式目标环境保持单独验收，不因本地恢复成功标记全产品完成。

## 当前接口和持久化

- GET `/api/workflow-tasks/:id/assignment-candidates`：`mode=transfer/recover/recover-next`；最后一种另提供 `nodeId/originalAssigneeId`。按本人任务或恢复范围校验，筛选启用且同时具备 approve/reject 权限的目标，投影姓名并排除自审、当前分配和重复票位。
- POST `/api/workflow-tasks/:id/transfer`、`recover`：闭合输入 `expectedRevision/targetUserId/reason`，必须携带稳定 Idempotency-Key；返回同一任务 ID、新 revision 和 assignment 事实 ID。
- POST `/api/workflow-tasks/:id/recover-next`：额外输入实际阻塞的 `nodeId/originalAssigneeId`；返回实例覆盖 revision。只保存覆盖，不代替原处理人提交批准。
- GET `/api/workflow-exceptions`：授权范围内运行待办分页，返回当前分配资格及实际下一阻塞票位。total 表示可检查的运行待办数，页面不将全部记录称为故障。
- 018迁移增加原签署票位、实例覆盖及不可变分配事实。业务→实例→任务锁序、历史/审计/Outbox及命令回执同事务，001至017校验和保持。权限分别为 `workflow:transfer` 和 `workflow:recover`，接口不依赖前端过滤。

审批中心菜单和路由允许 todo 或 recover 任一权限；只有 todo 时加载本人待办，只有 recover 时加载恢复检查。没有真实租户上下文时保留原开发演示。新增检查不要求恢复操作者取得配置或审批权限。

通用业务通知允许服务端生成的 `/business/records/<id>` 链接，worker 实际持久化通知并去重；外部、脚本及无关路由仍拒绝。通知和分配历史都不授予额外详情权限，历史读者撤销当前业务审批读取资格后仍被拒绝。

## 迁移和回滚

018只应用于独立开发/验证数据库，原R1包及部署保留。上线前备份并在独立环境执行迁移和完整恢复演练。可通过撤销 transfer/recover 权限关闭新增操作入口，保留018及当前兼容API，既有业务继续运行。完整代码回退须同时验证旧API的迁移readiness与数据库兼容；不能直接删除分配事实、改原签署票位或自动down migration。数据恢复应进入新实例并核对新增业务与历史，不能覆盖活动库。
