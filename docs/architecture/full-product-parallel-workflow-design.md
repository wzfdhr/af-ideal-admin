# 并行分支与会签的实施边界

FP-014进行中，当前增量尚非完整正式模块交付。工作流v1/v2保留旧义，v3显式支持并行与会签。必须实现真实多个活动分支、汇合和多人签署，不能用多人名单或画布节点代替执行。

1. 保留v1串行及v2条件协议；下一格式显式定义fork/join配对、分支标识和会签模式。解析器、客户端迁移、包依赖和发布门禁同时识别新格式，新增正向格式及未知未来格式拒绝用例，不静默改旧快照。
2. 并行节点产生2至10个活动分支，各分支可含审批、条件、抄送及嵌套并行。必须全部进入该fork配对的join，不能跨入兄弟分支或提前结束。静态拒绝环、悬空、不匹配汇合、非互斥重复活动、无审批路径与无法结束；明确支持的图边界。
3. 新增带租户/实例/父组关联的耐久activation/token及join group，记录每条分支位置和状态。现有单current_node_id不能作为多个活动分支的真实状态；保留旧实例适配，v3按活动记录执行。新迁移扩展任务唯一性/FK，不改001至016校验和。
4. 会签节点有固定参与者及all/any/quorum规则。批准达到阈值即推进，拒绝导致剩余可批准数不足即失败；中间投票保持等待。规则满足时未处理签署明确取消并留事实，不能再提交旧任务。并行join须所有活动分支完成，只有一次后续激活。
5. 每次命令仍按业务→实例→活动/组→任务一致锁序和CAS执行；角色实时鉴权、分配人和对象权限校验。投票、活动/组状态、业务状态、history/outbox/审计和下一任务同事务；重复key重放、独立并发key只产生一份效果。任一拒绝/撤回按定义取消所有剩余活动与待办，拒绝或撤回不能只取消当前分支。
6. 发布检查全部潜在人员及字段，提交按固定数据计算实际活动路径及参与者，自审拒绝；运行中选中处理人停用/撤权不绕过，保留可恢复状态。进程重启从数据库继续，汇合不依赖内存计数、浏览器状态或重新取当前草稿。
7. 设计器提供分支/配对join及会签阈值配置，审批中心可看各活动分支和签署进度，多账号能同时处理自己的待办。保存重开、包跨租户重绑、不可变发布、错误输入恢复及1280/1440键盘/界面均走真实服务。
8. 验证多活动分支、任意完成顺序、同组并发最后票、重复处理、拒绝阈值、剩余任务取消、条件和嵌套汇合、故障回滚、实际进程替换/恢复、双租户及权限负向，保留完整R1/条件流程回归。远端CI必须匹配提交；新部署、备份恢复、回退及正式目标环境保持独立门禁。

FP-015转交/异常处理及FP-016耐久超时调度仍按其独立语义继续实施，不将其删除或算作本次会签完成。原R1部署/包/卷保留；涉及新协议/迁移时先在专属demo验证并保留回退依据。

当前实现协议为workflow v3，节点类型parallel/join/sign：parallel.config.joinId与join.config.forkId准确配对，edge.channel为branch-1至branch-10；sign复用approvers并声明voting.mode=all/any/quorum、quorum仅定额模式使用。历史新增fork/join/sign/cancel，实际活动表workflow_activities保存归属与计数。当前同一实例每个静态节点只激活一次，静态结构限制在配对join前不能跨分支共享活动；支持嵌套及分支内互斥条件。所有事实在原事务内写入，原snapshot不改写。

回退保留017及已写事实，不删除已存在活动/签署；旧二进制不认识v3时不能执行/读取该定义，不能假装直接降成v1/v2。新部署/恢复及兼容回退仍须正式交付证据，当前开发demo不是生产验收。
