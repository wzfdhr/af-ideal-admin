# 通用业务记录与设备领用模板实施方案

状态：FP-010/022 进行中。设备领用是请假之外的第二个业务类型，使用同一发布快照、审批实例、任务、历史、审计和通知，不另建设备审批引擎。

## 迁移和兼容依据

010 将原 leave_requests 表改名为 business_records，保留表对象、原主键、数据和外键引用；增加不可变 record_kind。请假兼容视图 leave_requests 仅显示 leave 记录，可更新且带检查选项。R1 代码仍通过兼容视图运行，公共审批引擎通过基础表读取和更新两种记录，只有一份业务状态。

generic 记录没有请假天数，half_day_units 必须为空；leave 仍必须有合法半天数。新增 JSON 对象检查、业务记录与发布类型检查、实例与记录发布版本组合外键，防止串用类型或版本。不存在的发布引用仍由原外键拒绝，不用新触发器掩盖旧23503边界。010 在独立集成库先验证，只有回归通过后才能应用专属开发库；应用后追加新迁移，不能改已应用校验和。

## 记录与审批语义

业务记录创建、部分草稿保存、完整提交和撤回要求相应业务权限、幂等标识及更新版本。身份、租户、状态、历史和审批实例由后端产生，不能从浏览器传入。创建/修改回执只带标识和版本，不能通过旧回执恢复业务字段。

详情允许本人、实际分配过任务的处理人及执行抄送后的授权收件人；应用配置管理员本身不取得他人的业务详情。服务端读取事务刷新当前权限。待办仍按真实处理人查询，任务决定、串行推进、异常回滚、历史顺序、撤回取消和发件箱复用公共引擎。通知只带授权入口，generic 链接进入业务详情，leave 保持原入口。

记录固定引用发布快照。新发布不改运行中的旧实例；旧草稿遇活动版本变化返回冲突，只有同一应用的显式版本迁移才能换快照，跨应用迁移拒绝。UI 迁移须确认并提示被移除字段，不静默丢弃。归档阻止新建/保存提交，历史处理继续运行。

## 表单与设备领用模板

表单复用已有渲染器，新增有限的 integer/decimal 校验元数据。整数只接受约定范围，金额至多两位小数并规范为十进制字符串，禁止对象、数组、指数或任意脚本值。字段来自发布表单，浏览器不能增加总额、身份或其他未登记字段。部分草稿允许未填必填项，提交时完整校验。

计算字段只支持已登记整数数量乘以金额，输入必须引用普通字段，不允许递归计算、表达式或脚本。金额计算使用整数分，结果不接受浏览器覆盖。计算配置在设计器保存/迁移中明确保留，未来格式仍拒绝。

设备领用模板提供设备名称、领用数量、可选参考单价和领用用途，保存真实配置并选择当前租户审批人员，经公共发布及运行链路使用。模板不是静态成功回执；需要本人填写、保存、提交及真实审批。

## 验收与回滚

分别验证原R1、采购正向、金额/非法字段、双租户/多账号、同版本竞争、失败注入后的事务恢复、撤回、权限撤销、显式迁移、历史快照和真实API进程替换。浏览器另验证渲染、保存刷新/重开、真实任务入口和通知。

应用010之前备份原数据；完整目标阶段还需恢复到新实例验证。旧二进制只理解请假兼容视图，不能接管 generic 处理；回退时须保留当前数据库和兼容服务、隔离新业务入口，不能删除新业务记录或把它伪装成请假。完整备份恢复、部署回退与容量证据未完成前，FP-010/022不勾完成。

后续仍需通用业务的拒绝重提/关联、细分对象和字段范围、完整复杂表单/受控数据源、高级流程，以及全产品部署与交付验收；首个通用类型不替代这些冻结任务。
