# 全产品真实报表、导出与持久调度实施方案

对应冻结任务 FP-025、FP-026、FP-027，来源为全产品 Goal、能力地图报表中心、T-354 及已有报表入口。2026-10-13 核对时，当前列表、趋势、分布、明细、导出任务、定时报表和审计仍使用 Mock；`scenario` 可以模拟完成任务，下载地址指向 `/mock/report/`，不能作为真实查询、文件或调度证据。本文件是下一批实施方案，不是这些功能的完成记录。

## 范围与顺序

沿用 Vue/Arco、Fastify/PostgreSQL、共享 contracts、独立 worker 和本地对象存储。先打通同一条真实路径，再补既有规划中的其他报表和格式；不删除固定/自定义报表、趋势/分布/明细、字段权限、归档或定时任务要求。

| 子项 | 真实使用场景与交付 | 依赖及验收 |
| --- | --- | --- |
| FP-025-A | 授权用户查看真实通用应用记录的数量、按日趋势、状态分布和分页明细；显示口径、查询时间及数据范围 | 当前应用/记录权限、固定来源注册；数据库、双租户和无权限负向 |
| FP-025-B | 固定报表及受控自定义报表配置保存重开，选择登记字段/聚合/过滤，发布固定配置快照 | 禁止 SQL、脚本和任意数据源；新版本不改变旧导出计划 |
| FP-025-C | 补已有规划中的数据源、字段脱敏、空/错误/过期反馈及真实页面替换 | 服务端投影及过滤同一授权；不能用隐藏列代替脱敏 |
| FP-026-A | 创建耐久导出计划，worker 生成实际 CSV bytes，用户看到状态/失败并下载同一文件 | 当前查询、原创建者授权复验、文件摘要、唯一效果、真实下载授权 |
| FP-026-B | 补既有入口要求的 XLSX/PDF 等格式、归档/保留/清理及授权审计 | 未接真实生成器前明确不可用；CSV 首条路径不代表全部格式已完成 |
| FP-027-A | 保存/启停定时报表，实际到期生成固定运行记录与导出任务 | 固定时间规则、不可变 occurrence、租约/重启恢复、幂等/版本 |
| FP-027-B | 接收范围、失败告警、权限变更、时区/边界及模块部署恢复 | 复用已实现消息事实；外部通道仍受配置和发送授权约束 |

## 查询与字段授权

受控来源目录先登记 `application-records`，只查询真实 `business_records` 及其应用/发布快照。现有 `queryLowCodeSource` 的数量/趋势/状态分布 SQL 可参考，但不能直接沿用其 `fields::text` 搜索和全字段返回；未授权字段不得进入过滤、分组、排序、导出或错误信息。

报告权限不能扩大来源对象权限。每次查询、配置读取和导出执行都重新检查当前租户、当前账户/会话、报告权限、应用准入及来源对象范围。数据范围沿用真实记录领域的当前规则，`all` 只表示当前租户中当前有权的记录；审批人曾参与一条业务不等于能读取整租户报表。

现有 business 列表只有本人且要求 `business:read:self`；单条 `visibleRecord` 还允许当前具备 todo/approve/reject 任一能力的真实任务/分配参与者，以及当前具备业务读或审核能力的真实抄送事实持有人。历史任务/分配身份保留，当前能力撤销后该事实不再授权。`application:list/configure` 不赋予记录权。应从 record-access 抽取同一授权 SQL 谓词，让明细、count、trend 和 distribution 都从同一 `visible_records` CTE 取数，不能先分页再丢弃未授权行、也不能沿用只查本人的列表后宣称已经覆盖审核/抄送授权。

来源通过同租户 `application_releases` 关联固定的 applicationId 和真实记录版本；不相信客户端 releaseId，也不因能管理应用元数据就放行其全部记录。业务字段由各记录固定的发布快照解释，不用最新草稿重解释旧值；同名字段跨版本语义或类型不兼容时显式拒绝/分版本查询，不静默拼成同一列。

字段由登记来源的服务端目录列出类型、可查询/聚合能力和所需字段权限。未知字段、未授权字段、原租户引用及未来格式拒绝。明确返回可见字段和隐藏原因，不能把完整敏感数据先交给前端再遮盖。关键词只作用于当前获准的字段；数量和分布同样使用授权后的来源集合，不能从总数推断被隐藏业务。

时间筛选必须含时区或使用明确业务时区与有界日期区间；指标定义记录使用哪个事实时间、包含哪些状态及是否包含删除/归档记录。查询响应带来源/口径版本、实际查询时间和数据截止时间。新提交会影响下一次查询，不偷偷更改已经固定的导出快照。

## 导出模型、文件和下载

追加独立迁移，旧 001 至 023 校验和保持。按领域建立报告配置/发布版、导出计划、执行事件、导出制品、调度规则和调度运行事实；不使用一张可任意解释 JSON 表伪装全部能力。

导出计划固定报告版本、来源、字段、过滤条件、创建者与授权依据。客户端不得提交输出内容、完成状态、结果人数、文件路径或租约。创建/取消/重试/归档使用命令 key、expectedRevision 和事务审计。创建回执只证明计划已持久化，`completed` 必须有实际文件、大小/摘要及完整效果事实。

worker 领取持久租约，效果前重新检查原创建者的当前权利。权限已撤销时阻塞或拒绝，不借管理员重试权限替代原主体；最大尝试、退避、租约死亡和失败原因可查询。固定效果身份确保恢复或重复触发不生成两个可见结果。实际文件先写入受控临时对象，复用真实扫描器确认通过后，再按确定身份提交制品和事件；扫描失败/感染保留实际状态并禁止下载，事务失败/进程中止留下的对象需由清理器按数据库引用安全回收。

`LocalObjectStore` 的 put/get/remove 和摘要可复用，但不能把报表文件简单登记为无绑定的个人 `stored_files`：现有所有者下载只复验文件权限，可能绕过已经撤销的报表/字段权限。使用专属报表制品下载路由，或同时扩展所有通用文件读取、预览、列表的报表绑定授权，先补失败回归再开放入口。

当前对象清理器仅认识 stored_files/file_parts。新制品对象必须进入统一存活引用及清理规则，否则合法归档可能一天后被误删。归档保留与临时失败文件的 TTL 分开；删除字节不删除历史审计和计划事实。

下载重新验证当前报告、来源对象和计划中各字段权限。若权利比生成时收窄，旧固定文件必须拒绝下载或要求重新生成，不能继续提供包含已撤权内容的旧 bytes。跨租户、猜测 ID、通用文件地址和预览接口必须得到相同拒绝。CSV 正确转义换行/引号和电子表格公式前缀；仅通过实际生成与字节检查后才声明对应格式可用。

创建/执行/下载/取消/归档的事实审计由服务端在对应事务内产生，使用受控 ID、摘要、数量和错误码；不记录完整业务内容。现有 audit 查询将 auth 映射到 security、其他事件映射到 operation，必须扩展真实 export 类别及权限筛选，才能支撑现有导出审计入口。浏览器 POST audit 只属于 client_telemetry，不能据此宣称导出或下载已发生。

## 持久调度与消息

调度规则使用闭合日/周/月及明确时区模型，校验真实日历、时间和下次执行；禁止任意 cron 表达式、代码或外部命令。每个实际到期 slot 建唯一运行事实，固定当时的报告版本、规则版本和原主体，再创建对应导出计划。规则编辑、启停不能抹掉历史运行，恢复不能跳过未处理的当前事实或重复同一 slot。

独立 worker 和数据库事实负责租约、下一次执行及错误恢复；API 或 worker 重启后可从表中继续。停止调度只阻止后续 slot，已创建任务按其独立取消语义处理。原主体失权、来源不可用、未知版本、文件失败均保存真实错误；消息告警引用当前授权任务，不携带能够扩大业务访问的 requestId/access 字段。

接收角色/部门使用当前租户实际 ID 与当前启用成员。接收人不能直接取得发起者的宽范围制品；按每个接收人的当前行/字段权限生成，或只有数据权限交集足够时才允许共享同一制品。计划受众不授予下载权，通知提示也不替代当前授权。

## 所有权与检查

下一批执行者为本任务 Codex，可拆成共享契约/迁移与权限、服务端查询/执行器、前端真实报表三条明确文件所有权；共享入口/worker/存储清理由 root 整合，所有人保留其他并行改动。开始实现后再把任务状态改为进行中，提交及证据追加统一质量清单。

必须覆盖真实数据库/领域、多个账户/双租户、字段过滤/导出/下载撤权、命令并发/同 key、故障事务、worker 死亡与租约、实际文件 bytes/摘要/清理、保存刷新重开、调度唯一运行及真实浏览器。E2E 不能注入成功响应；Mock 单独保留。运行完整现有门禁与对应提交实际远端 CI，备份恢复到独立实例、新部署和兼容回退各自记录，不能由本地同库恢复代替正式交付。

关闭报告/调度入口并撤销对应权限可停止新操作；停用原规则且使用兼容执行器处理已固定计划。保留迁移、制品引用、历史运行和事件，不执行破坏性 down migration；旧服务不能识别新计划时不声称已经实现兼容回退。
