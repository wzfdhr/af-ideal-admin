# 低代码页面的应用包引用与重绑方案

FP-019页面包增量已实现，完整全产品交付仍进行中。低代码真实运行增量不代替跨租户导入；保留当前v1/v2表单/流程包、Schema/version校验和冻结范围。目标为在新租户/部署重绑页面及受控来源后，实际发布并通过同一业务/审批链路。

## 当前缺口及引用规则

旧v1/v2包包含表单、流程、人员及表单字典来源；新增v3包含低代码页面、来源符号和受控物料依赖。低代码来源绑定实际业务发布版且不可重定向，导入阶段目标应用尚未发布，因此不能填来源租户release ID、悄悄借别的租户发布版或提前伪造一个目标release。

新v3包明确增加page-contract v2、low-code-sources v1和受控Pro物料依赖。页面材料/动作仍使用已验证的闭合v2格式，所有页面/来源ID转换为包内符号，原app/page/source/release UUID不出现在可移植引用中。人员、字典来源和页面来源有各自完整映射清单，不用一个字符串表模糊替代不同类型。

业务记录来源只可声明包内根应用或明确的受控依赖；若页面固定的业务发布版与导出的表单/流程定义不等价，导出应拒绝并给出需选择/发布版本的解释，不能把旧页绑定到新规则。其他应用引用必须显式列出或拒绝，不能按相同名字猜测；登记字典来源在目标租户逐项绑定及授权复验。

不导出业务行数据、查询缓存、浏览器token、凭据/授权头、默认敏感输入、病毒样本、文件对象或原租户范围。配置展示文字、权限码及物料参数也须闭合校验；未知未来格式或未登记物料/动作拒绝，校验和覆盖整份定义与映射依赖。

## 目标导入和发布生命周期

1. 验证v3包/摘要/依赖/所有符号引用及当前用户的应用导入、页面、来源权限，在目标租户真实创建独立应用/草稿和受控待绑定页面定义。回执明确“页面等待目标业务发布后绑定”，不能写已发布/可运行；同key回执与事实保持幂等。
2. 用户在目标应用配置页重验表单、人员及业务规则，按原组合发布API产生真实目标release。包不能使模型或导入过程绕过人工发布确认。
3. 通过明确的页面重绑命令，以目标app/release及expectedRevision解析包内application来源，登记目标租户自己的low_code_sources、创建真实页面草稿并返回page/source映射。命令须重新验证当前权限、目标发布版、字典授权、格式/列/动作和资源归属；失败同事务回滚，无半个有效页面或静默丢引用。
4. 用户检查/编辑页面，按既有low-code publish发布，再由目标租户员工实际查询、保存/提交、审批、刷新和跳转。旧来源租户模板、业务和发布指针保持原样。

待绑定定义使用独立领域状态与租户/应用FK，不伪装为已经通过运行校验的low_code_pages；关联原包hash/任务/错误/事实及恢复阶段。重启后能读回并继续，权限撤销后缓存回执不泄露当前不可见映射。状态/事件/审计和命令回执保持事务一致，重绑不能改已有不可变来源身份。

## 验收及兼容回退

- 契约覆盖v1/v2保留、v3正向、未知v4/脚本/URL/未来物料/错依赖/缺引用拒绝；大小边界、摘要和来源脱敏有实际证据。
- 源租户导出实际文件，目标租户导入→业务发布→重绑→页面发布→员工业务→两人审批；原始跨租户/缺权限/伪造release或来源映射不得产生有效页/业务实例。真实E2E不注入成功响应。
- 故障回滚/原key恢复、并发重绑/唯一效果、API/数据库重启、目录超过100条及引用查找、新部署/备份/回退和对应提交CI分别记录。
- 新迁移追加在020之后，既有迁移校验和保留；只在备份后的专属环境执行。关闭新导入可撤销权限并保留待绑定事实与兼容API，不删除页面/来源或自动down migration。旧执行器不接受新包依赖，不能降级丢页面后宣称导入成功。

实际执行者为本任务Codex。本方案保持应用包、低代码页面、物料和真实权限的既有范围；更多外部来源、插件物料和正式目标部署仍按对应任务实施，不把方案或导入回执计作FP-019完成。

## 已实现接口与迁移

追加021_package_pages.sql，保留001至020及既有发布/业务快照。application_package_page_sets持久化pending/bound、不可变包定义和字典映射；application_package_page_bindings存放不可变目标页面对应事实。应用、发布、成员和页面采用租户复合FK；bound的引用/版本/时间不可改写。

- POST /api/application-center/:id/package：旧请求保留v1/v2；显式pageIds选择最多20个已发布页面后生成v3。包以UTF-8字节检查256KiB上限。
- GET /api/application-center/:id/export-pages：按当前租户、页面元数据范围返回关联的已发布页，导出命令复验来源与业务定义，不依赖名称匹配。
- POST /api/application-packages/import：v3人员与字典槽逐项映射，创建独立业务草稿和pending页面集合，回执明确未发布/未运行。
- GET /api/application-center/:id/package-pages：按当前导入权限及创建者范围读取恢复阶段和实际引用表。
- POST /api/application-package-pages/:id/bind：expectedRevision、applicationReleaseId和Idempotency-Key。目标应用当前已启用的实际发布版才可绑定；创建来源/页面/审计/映射/回执在同一事务。失权、停用字典、字段不兼容、跨租户、故障均不留下半个图；相同key复验当前权限后返回原事实，竞争key只完成一次。
- GET /api/application-packages/people、sources：保留数组响应，支持current/pageSize（上限100，默认100）。导入UI完整读取各页，后续页错误拒绝整个目录，不能使用截断映射列表。

配置页的待重绑按钮在目标业务发布前不可用；成功后按实际pageId直接打开页面编辑器，刷新仍读取该页面，不受首100项列表影响。页面仍需单独检查和人工发布。已有无页面v1/v2包维持下载/导入路径。

## 当前证据与保留门禁

实际日志位于test-results/full-product/page-package-20261003/。契约、真实跨租户API和浏览器、故障/幂等/竞争、即时撤权、页专用字典、超过100项目录、API替换与独立pg_dump/pg_restore各自验证，不互相代替。恢复脚本scripts/verify-page-package-recovery.mjs只操作显式本地demo及随机目标库，原库待重绑状态保持；该恢复不等于全新机器部署或全产品回退。

本批只支持闭合v2页面、包内根业务及已登记字典；跨根应用依赖需后续显式协议，当前明确拒绝。插件物料、外部HTTP源、全物料市场、目标部署/兼容版本迁移/容量和完整主题键盘分辨率仍按冻结任务推进。新依赖的包不能交给只支持v1/v2的旧导入器，不通过静默丢页降级。关闭页面包入口可以撤销导入/页面权限，运行页另按运行和业务权限控制；保留021/已创建事实及支持v3的执行器，不自动down migration。
