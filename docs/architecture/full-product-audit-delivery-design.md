# FP-030/031 真实事实审计检索与治理边界

本增量接续冻结 FP-030/031、T-402/404：先完成当前模块的事实分类、授权检索、脱敏和实际页面，再完成独立保留、归档、真实导出及恢复。当前 `audit_events` 已由服务端在业务事务内追加；客户端 `/audit/events` POST 只产生 telemetry，不能伪造事实。本文是实施决策，不是模块验收记录。

## 事实来源与事务

- 保留现有认证、权限、应用/表单/流程、业务、文件、消息、低代码、报表/调度和大屏事实的同事务写入。原始 Goal 要求业务状态、历史、事实审计、通知事务一致，此要求优先于旧 Mock 清单中“审计旁路不阻断业务”的概括，不将业务成功事实改为可能丢失的浏览器队列或异步 best-effort 写入。
- `audit_events`、`auth_failures`、`client_telemetry` 是不同来源。已有匿名认证失败没有可信 tenant/actor，不能以请求中的 tenant/username 推断授权，更不能仅凭租户 `audit:read` 读取全局失败记录。FP-030 先提供已认证、可绑定实际租户的成功/失败事实检索；全局匿名安全边界单列，不能伪造归属。
- 保留原始 append-only 事实与 ID/trace/time。旧调度动作曾统一写 success；检索的版本化投影对已登记的 run/recipient failure、blocked、partial-failed 动作显示实际失败结果，新写入采用正确语义。重试命令本身成功与实际投递失败分开，不重写旧行或按不受控子串猜测所有未来 action。
- 请求错误记录失败不得改变原始拒绝结果；新增脱敏的失败观测计数/阶段和耐久诊断边界，不能把静默 catch 当成可观测，也不能在日志写 token、口令、请求正文或原始数据库错误内容。

## 闭合契约、查询与当前授权

- 共享 v1 查询包含 current/pageSize、module、eventType、result、operatorName、targetId、traceId、明确起止自然日与 IANA 时区。页大小最大100，日期和字面值严格校验，未知键/非法未来格式拒绝。兼容原有双日期参数时保留两个位置，单边结束日期不得变成开始日期。
- traceId/targetId 精确匹配服务器事实，operatorName 按当前获准投影做 literal 搜索，百分号和下划线不是通配语义。来源、事实时间、分类版本、当前结果与查询边界明确返回；结果少不等于无审计事实。
- 每次查询在 `authorizedTransaction` 内重新验证会话、租户、`audit:read` 及历史 actor 的当前角色/部门/本人范围。不能只验证权限码就读全租户；旧失效会话、停用成员/租户和撤角色立即限制后续访问。默认服务端返回事实元信息，不授予原业务正文、报表行或附件字节。
- count/list/筛选/排序使用同一受权事实集合和SQL语句快照，稳定 createdAt+id 顺序，有限分页。新的索引只追加028+，001–027已应用迁移及其校验和冻结。

## 分类与内容投影

- 用登记的模块/action 将权限更改、认证、导出与一般操作分到已有公开类型；字段白名单、类型、最大长度和来源版本由后端控制，浏览器不能请求任意 detail/JSONPath。
- 所有模块 detail 都走事实白名单。允许必要资源引用、版本、动作、有限尝试及规范错误码；不因 audit 权限返回业务正文、审核自由文本、报表捕获数量/文件指纹、凭据或完整个人联系字段。原 report-export 的保护继续保留，其他模块不得成为旁路。
- actor 标识/姓名按当前成员字段范围投影；隐藏值不参与关键词过滤、排序或产生可见聚合。未知旧模块保留最小事实和空 detail，不把历史未经审核的 arbitrary JSON 原样送给浏览器。
- server facts、匿名认证失败和 browser telemetry 的 source 标识不同，前端只显示对应可信来源，不把 telemetry 标为操作成功。

## 实际页面路径

现有审计页接同一共享查询/DTO，提供真实分页、精确trace/对象筛选、模块/类型/结果、独立起止日期/时区、来源与分类版本、明确 loading/空/权限/错误态。查询失败保留输入；旧响应在身份/租户/查询变更后丢弃。刷新、关闭重开与当前撤权都经真实API验证；Mock保持独立开发边界。

## FP-031 后续保留、归档、导出

- 审计使用独立的治理权限、policy/jobs/artifacts/events；不得借用 reporting/source ACL 或普通文件 owner ACL。归档/导出固定实际受权查询、截止时间、原事件 IDs、投影版本和字节摘要，写命令具有幂等键、revision及当前权限复验。
- CSV/XLSX/PDF的真实生成可复用已验证格式能力，但输入是审计自身的有限事实投影；所有字节经实际 ClamAV 扫描，元信息与实际下载都走独立审计授权。超限明确拒绝，不把第一页当全部导出。
- 异步领取、续租、fence、有限退避、取消/重试/过期和终态事件/审计维持一个真实效果。新对象必须加入活跃引用集合和一致性文件bytes备份，不能让普通孤立清理删除审计制品。
- 保留/归档是新的授权生命周期，不直接关闭旧 append-only trigger 或改历史迁移。物理purge须明确、受控的维护范围和已验证可恢复副本；未知结果不能删除未经确认归属的对象/库。制定默认保留范围时区分演示数据和正式策略，不能虚构法律批准、强制法定天数或客户政策。

## 独立门禁与回退

FP-030 需契约、真实SQL、多账号/双租户UI、非法输入/当前人员及字段范围、失败/trace/真实分页、重开/进程替换及对应SHA的CI；FP-031 再补实际制品/扫描/权限撤销、并发领取、故障/SIGKILL、归档/到期、同快照数据库与实际bytes恢复。匿名全局检索、正式保留策略、新机器部署、二进制兼容回退及正式交付单列门禁。

回退先停用新增治理/外发入口并保留原始事件、trace、发布状态及兼容读取器。不能以 Git 回退代码为由删除新表、篡改历史事实或称已完成新物理实例恢复。整体 Goal 保留全部后续能力，当前决策不替代实现或验收。
