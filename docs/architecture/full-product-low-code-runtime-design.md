# 低代码动作、受控来源与发布运行实施方案

FP-017/018进入差距核实与设计，当前没有真实后端实现或验收结论。范围仍为LA-038/039及T-610：五种动作必须产生实际效果，页面可配置生成或渲染完整管理路径；权限、保存重开、预览/发布、灰度和回退一致。应用包及物料复用按FP-019继续接入，不因当前包已支持表单/流程就省略页面。

## 当前源码缺口

- `src/components/low-code/builder/index.vue:runAction`仅让query/refreshBlock共享一次预览，其余动作只修改提示文字；ProForm只读、图表显示Mock总数，不能证明写入、路由、弹窗或目标区块刷新。
- `src/api/low-code.ts`已有页面保存/发布/回退及来源预览接口，但reference-api没有对应模块。真实租户的路由/菜单也没有低代码能力入口。
- 当前v1来源包含任意url/method，props/params为开放对象，normalizeVersion不拒绝未来版本。真实模式不能将这些值变成任意HTTP代理、脚本、组件路径或数据权限表达式。

## 首条实际使用路径

配置管理员创建“设备领用管理页”：查询表单→授权业务记录表格→打开新建/编辑弹窗→真实保存→刷新该表格→打开同一授权详情→实际提交审批。复用已交付应用发布版、FormRenderer、业务记录事务、审批/文件/通知/审计和ProTable/ProForm，记录旧发布版及在途历史，不再编写一套专用设备系统。

随后提供实际记录数量/状态分布/按日趋势的统计和图表物料，口径以授权范围内的持久化数据为准，空/错误/过期明确显示。用户和其他资源的来源必须复用原模块授权和字段投影，不能借页面run权限获得管理员数据。

## 配置和来源

引入闭合v2页面格式；有界材料、字段、动作、布局、参数绑定及引用。未知未来v3拒绝。v1继续服务显式Mock，兼容转换先校验等价字段，无法受控转换的url/脚本/私有数据明确拒绝并保留原草稿，不能丢字段后伪称成功。

独立低代码领域表保存草稿/revision、不可变发布快照/内容hash、活动发布指针、灰度策略及版本历史。沿用tenant复合FK、稳定命令key、expectedRevision和事务审计；配置写入不能兼作业务提交。

来源以服务端登记key解析为固定适配器、操作、参数契约及所需权限。第一批使用已有应用业务记录及注册字典能力，随后复用系统管理和报表来源。登记元数据不携带URL凭据、授权头或生产行数据；原租户应用/字典引用以明确映射关联，源不可用或撤权后运行拒绝，不能回退Mock。

页面可见、区块可见和动作可见只是界面规则；每次运行还要检查当前成员、页面发布版/范围、来源权限及对象/字段权限。正文不保存用户token或查询到的行数据。必要的表单初值仅来自当次授权读取；字段不可读时不能将掩码或空值作为原值覆盖提交。

## 五种动作的可执行语义

| 动作 | 实际效果 | 约束及恢复 |
| --- | --- | --- |
| query | 读取登记来源、把结果及分页写入明确目标表格/图表 | 类型化参数、后端范围/投影、超时/错误及旧响应丢弃；空结果有别于失败 |
| submit | 以真实API和幂等命令保存或提交业务，回执后更新对应资源状态 | 来源登记限定命令、复用领域校验/版本/事务；422/409保留输入，不写页面草稿冒充业务成功 |
| navigate | 前往共享白名单路由所指的资源详情 | 类型化路由目标及受控参数，不执行外部URL或javascript；目标仍重新鉴权 |
| openModal | 打开明确弹窗材料及其已授权表单/记录上下文 | 无效目标拒绝；焦点、关闭/取消、未保存保护及字段权限实际生效 |
| refreshBlock | 重新查询指定区块的登记来源并替换该区块结果 | 不只刷新统一预览；保持其他区块输入，校验目标/来源并避免迟到响应覆盖 |

受控发起流程使用现有业务submit端点，不提供脱离业务事务的任意启动入口。参数绑定使用有限的字段/选择行/常量引用，不解析JavaScript表达式。动作只能引用当前页面材料和已登记来源，服务端不能相信客户端传入的权限码或tenantId。

## 发布、运行、灰度和迁移

编辑与运行分离，预览使用当前未保存配置和同一受控执行器，并显式标识状态；发布后固定配置及来源引用。已存业务按自己的发布快照读取。关联应用版本变化必须给出冲突和显式更新路径，不能将旧页面表单绑定到新规则后默默提交。

灰度按租户/用户稳定选版，支持明确0/100及受控百分比，刷新/重开保持选择；回退只改变活动指针/策略，不改旧快照。运行入口有 loading、空、错误、无权和配置过期状态。

应用包增加明确页面/物料/来源依赖及引用映射，在目标租户重新绑定并发布真实运行。导出不包含凭据、浏览器查询缓存、默认敏感输入或原租户越权ID；当前表单/流程v1-v2包保留原语义，新依赖不能伪装成旧能力。

## 实施和验收

1. 补动作/来源闭合契约和失败回归、页面/发布存储及权限；原R1、v4定时和现有Mock回归保留。
2. 完成实际业务记录查询/保存/提交与五动作运行器，再接配置UI、重开/发布和完整管理页材料。
3. 接入真实统计/图表、灰度/回退、包映射和物料复用，逐项保持格式及权限负向测试。
4. 多账号双租户完成设计→保存重开→预览→发布→员工实际业务→审批→刷新/跳转；原始非法/越权请求不得产生实例或数据副作用。真实E2E不注入成功响应。
5. 并发/幂等/错误恢复、API及数据库重启、布局/键盘、备份/新部署/兼容回退与实际远端CI分别记录。计划、Mock或一个按钮提示不作为FP-017/018完成。

实际执行者为本任务Codex。原冻结范围、LA编号及正式交付标准保留；本方案不构建任意脚本平台，也不把未接入来源标为可用。迁移只在备份后的专属验证环境开始，保留原R1及既有卷/发布版，不自动down migration。
