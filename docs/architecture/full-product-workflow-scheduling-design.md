# 耐久流程超时与定时节点实施方案

FP-016进入设计，当前没有真实调度实现或验收结论。依赖FP-015的固定分配/恢复语义，保留v1串行、v2条件、v3并行/会签及旧发布快照。实施继续使用PostgreSQL与现有worker入口；报表、消息发送任务仍按各自FP编号落地。

## 可执行场景和配置边界

1. 审批或会签超过发布时配置的期限，产生一次真实站内提醒及服务端定时事实，原任务和签署阈值继续有效。转交后提醒实际当前处理人，停用/撤权目标进入明确恢复状态。期限不自动批准、驳回或跳过审批。
2. 新增显式定时等待节点，到期后恢复该实例的实际下一条路径。等待节点保留并行父组与分支归属；只有所有真实分支到达配对join才汇合。等待点不是一份可由用户批准的伪待办。
3. 多worker竞争、领取后崩溃、效果事务前后崩溃、数据库/进程重启后继续，同一节点到期只产生一次实际效果。服务停机期间的到期任务恢复后补执行，记录计划时间、实际执行时间和延迟。

v4增加闭合的等待节点配置及审批/会签期限配置，延迟使用有界整数秒，计算以数据库UTC时刻为准。拒绝负值、无限值、任意脚本、外部URL和未知配置；未知未来v5继续拒绝。v1至v3不被默认为带定时动作，不重写已有发布快照。所有完成路径仍须经过真实审批或会签。

## 数据和事务

- 新增019迁移，001至018保持校验和。流程定时表保存tenant/instance/release/node/activity、触发类型、due_at、状态、revision、attempts、next_attempt_at、lease_until、claimed_by及有限错误码。复合租户FK和节点触发唯一约束阻止串租户或重复创建。
- 独立定时事实保存计划时间、执行结果、尝试及服务端来源。自动执行必须明确标为调度服务，审计/历史不能将worker伪装为申请人的主动审批；这部分在迁移和DTO中显式处理，不能复用空会话绕过人类命令授权。
- 当前audit_events已允许actor_id为空，而workflow_history要求真实成员operator_id。019须为自动事实提供明确的system来源及受约束的空操作者投影，保留全部既有成员事实；使用专用服务端事实写入函数，不能将申请人的userId配上“调度服务”名称。人类命令仍走原authenticate/authorizedTransaction，调度器只走有限的系统执行上下文。
- 节点进入、timer创建与业务/活动/history/audit同事务。worker先用SKIP LOCKED短事务领取并设置租约；执行事务按租户授权状态→业务→实例→活动→timer锁序重读，检查claim/revision及实际状态，再原子写效果与完成标记。领取锁不能跨外部等待或升级成业务锁。
- 原处理批准、驳回、撤回、阈值达到或全流程结束时取消不再需要的timer。转交不重置原期限，唤起与转交/撤回竞争时不产生终态后的新待办。结果通知继续经Outbox唯一去重，不把消息延迟当作流程命令失败。
- 所有等待、汇合计数、触发标识和恢复依据从数据库和原release读取；应用当前草稿、浏览器计时器和进程内缓存不参与判定。保存的实例分配覆盖继续生效。

## 权限、故障和恢复

发布者必须具备配置/发布权限，全部配置字段和引用受后端校验。定时查询及重试使用独立权限并同时受租户/对象范围控制；仅知道timer ID不能读业务内容。worker没有通用脚本或任意写入口，只执行发布快照允许的动作，并复验租户、实例及当前目标资格。

暂时性失败有限退避，租约到期可重领，达到上限进入可查询failed；目标身份失效进入blocked，不静默跳过。授权恢复操作携带expectedRevision、原因和稳定命令key，仅允许重试实际失败/阻塞定时节点，仍复验前沿与目标。事实、attempt和错误码保留，不记录完整表单内容或凭据。

设计器提供期限/等待配置、保存重开和非法输入保留；运行详情明确显示计划时间、等待/超时/失败/恢复状态。审批中心只向对应权限展示恢复入口；同一会签多个票位和多个并行分支必须能识别对应活动。

## 回滚

迁移先备份并在专属验证库执行。配置和执行可通过能力开关停用，但已创建的定时实例必须显示暂停和人工恢复状态，不伪称继续执行。保留新增表、原发布快照与定时事实，不能删除timer来掩盖失败。完整服务回退先在恢复到新实例的数据上验证旧API的readiness/配置格式兼容；已有v4实例不得交给只支持v3的执行器。
