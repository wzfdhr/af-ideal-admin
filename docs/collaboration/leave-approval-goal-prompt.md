# R1 请假审批实施 Goal 提示词

以下内容是当前已建立 Goal 的约束文本，供后续接手复用；同一任务已有未完成 Goal 时继续执行，避免重复创建。

```text
请建立并持续推进以下 Goal，按仓库技术方案实施，直到 R1 请假审批应用达到可试点交付标准。

工作目录：
/Volumes/新加卷/Codex/桌面归档/af-ideal-admin

必须先阅读：
1. docs/architecture/leave-approval-delivery-design.md
2. docs/quality/leave-approval-delivery-tasks.md
3. 当前适用的 AGENTS.md、开发规范和发布检查清单。

一、目标与范围

完成 LA-001 至 LA-036，以及 AC-01 至 AC-20。

最终交付必须支持：
配置并发布请假应用 → 员工保存草稿 → 提交申请 →
主管串行审批、驳回或员工撤回 → 结果通知 →
工作台和申请详情更新 → 服务端审计可追溯。

必须具备真实数据库持久化、多账号操作、双租户隔离、
幂等与并发控制、生产构建、容器部署及备份恢复证据。

LA-037 至 LA-045 属于后续阶段，本 Goal 不主动扩展。
不得为完成 R1 顺带重写全站、替换组件库或建设通用 AI 平台。

二、开始实施前

核实实际分支、提交、未提交改动、依赖和运行环境。
文档中的 7194f59 只是评估基线，不能据此重置当前工作区。

保护用户已有内容。遇到 Git 元数据告警，先诊断和备份，
不得直接删除未知文件、执行破坏性 reset 或清理无关分支。

区分任务负责人角色和实际执行者，不虚构人员、验收人或批准记录。
可以根据技术方案作出可逆的常规技术决策，无须逐项询问用户。

三、实施顺序

按依赖依次完成：
M0 基线与契约 → M1 服务端业务闭环 →
M2 用户操作闭环 → M3 可试点交付。

优先完成一条可运行的纵向业务路径，再补齐同阶段异常场景。
前端可以使用 Mock 开发，但真实业务验收必须连接参考后端。

默认遵循方案中的现有 Vue 前端、独立参考 API、
PostgreSQL 和共享领域逻辑结构。
若发现已有可复用实现，先核实再复用，避免重复建设。

发现方案矛盾或实施缺口时：
先提出最小必要修正，同步设计、任务和验收要求，再继续实施。
不得通过降低验收标准、删除用例或缩减范围掩盖问题。
涉及业务范围改变或不可逆操作且缺少授权时，再请求用户决定。

四、实现要求

1. 发布版本不可变，在途申请固定引用原表单和流程快照。
2. 提交、审批、驳回和撤回必须由服务端验证身份、
   租户、权限、资源归属、状态及版本。
3. 业务状态、任务、历史、成功审计和 Outbox 保持事务一致。
4. 幂等重试不能重复创建实例、任务或通知。
5. 审批与撤回并发时，只允许合法状态转换，不得产生分裂状态。
6. 切换租户后，旧请求和缓存不能污染新租户数据。
7. 保存失败保留用户输入；冲突不得静默覆盖。
8. 正式环境不得回退 Mock 或暴露演示重置入口。
9. 保持现有功能兼容，公共契约变更必须有迁移说明。
10. 不在日志、源码、测试报告中暴露密钥、token 或用户隐私。

五、测试与验收

先为确认的缺陷建立能复现问题的必要测试，再修复。
按变更运行相应检查，并完成方案规定的全部阶段门禁。

验收证据分别记录：
领域单测、API 契约、真实数据库集成、
多账号浏览器操作、界面检查、部署及恢复。

以下情况不能算完成：
- 只有页面或按钮；
- 只有 Mock 成功响应；
- 只有单元测试；
- 只有构建成功；
- 只有截图或 PR；
- 未实际执行却声称通过。

真实 E2E 必须使用独立账号和浏览器上下文连接真实 API，
不能用拦截并注入成功响应代替业务执行。

必须验证：
刷新与关闭重开、服务及数据库重启、
重复提交、并发审批、审批撤回竞争、
跨租户访问、撤权、发布切换及备份恢复。

六、任务记录

持续更新 docs/quality/leave-approval-delivery-tasks.md。

只有实现、必要检查、对应验收和证据齐备后，才勾选完成。
记录实际提交、变更模块、测试结果、证据位置、
已知限制、迁移影响和回滚方式。

不要把文档完成当成开发完成。
不要只更新任务状态而不交付实现。
不得伪造测试、截图、运行记录或验收结论。

七、持续推进规则

不要停在计划、分析、脚手架或阶段性演示。
每完成一个任务，继续推进下一个满足依赖的任务，
无需反复询问“是否继续”。

遇到失败，定位原因、修复并重验；
遇到阻塞，继续处理不依赖该阻塞的工作。
确实需要外部信息时，给出具体阻塞原因、已尝试措施、
仍可推进的事项和用户需要提供的最少信息。

定期简短汇报当前完成项、验证结果和下一步。
用户询问进度时，回答后继续推进，除非用户明确要求暂停。

保持改动可审查、可恢复。公开发布、生产部署、
不可逆数据操作及向他人发送消息，遵循已有授权边界。

八、完成标准

只有同时满足以下条件，才将 Goal 标记完成：

- LA-001 至 LA-036 全部完成并有证据；
- AC-01 至 AC-20 全部实际通过；
- 所有规定的质量门禁通过；
- 无数据丢失、越权、重复审批等阻塞问题；
- 新环境可按文档部署；
- 已完成持久化和备份恢复演练；
- 已输出交付报告、已知限制及回滚说明。

最终报告明确说明实现范围、验证环境、提交版本、
证据位置和剩余限制。
结论限定为“R1 请假审批路径可试点交付”，
不能扩大为整个产品全部生产化。

现在从核实工作区和 LA-001 开始实施。
```
