# Code Review Checklist

本清单用于 reviewer 判断一个 PR 是否可合并。它补充 PR 模板，重点关注企业中后台框架的稳定性、权限、安全、Mock 闭环和可回滚性。

## 基本信息

- PR 已说明变更范围、验证命令、风险等级和回滚方式。
- 提交信息遵守 Conventional Commits。
- 变更范围聚焦一个任务或一个明确阶段，不混入无关重构。
- 没有提交生成产物、依赖压缩包、临时日志或敏感信息。

## 必须有测试的敏感区域

以下任一领域发生变更时，必须有测试：

- 权限：路由 `meta.access`、菜单权限、按钮权限、数据权限预留。
- 认证：登录、退出、token 读取/写入/清理、401/403 行为。
- 请求：请求客户端、错误处理、traceId、运行时 API 前缀。
- 表单 schema：schema 版本、迁移、导入导出、运行时渲染、远程数据源。

测试至少覆盖成功路径和一个失败或受限路径。只改文档时，应有文档结构或命令可执行性测试。

## 功能和 Mock 闭环

- 新功能在无后端环境下可以通过 Mock 完成核心演示。
- Mock URL、请求参数、响应结构与 `src/api` 类型一致。
- 页面具备 loading、空状态、错误态和权限态。
- 路由、本地菜单、服务端菜单 Mock、语言包保持一致。
- 危险操作有确认、失败可恢复、成功后状态刷新。

## 安全和合规

- 不在日志、错误上报、审计日志或 Mock 数据中暴露 token、密码、Authorization、身份证号。
- 服务端菜单只使用前端白名单 `componentKey`，不允许任意组件路径或脚本。
- 权限不足时不会仅靠隐藏按钮保护真实访问，路由和接口边界也要有约束。
- 运行时配置通过环境变量或 `runtime-config.js` 注入，不硬编码生产服务地址。

## 文档和可维护性

- 新增能力已补开发文档、接口契约或任务清单说明。
- 新页面优先复用 `ProTable`、`ProForm`、`PermissionButton`、字典组件和 UI adapter。
- 抽象只服务当前明确重复点，不引入未验证的通用框架。
- 命名、目录和测试文件与既有模块保持一致。

## Reviewer 判定

可合并：

- PR 模板信息完整。
- 必跑验证命令通过或有明确、可接受的跳过说明。
- 高风险区域已有对应测试。
- 风险等级和回滚方式可信。

暂缓合并：

- 缺少变更范围、验证命令、风险等级或回滚方式。
- 涉及权限、认证、请求、表单 schema 但没有测试。
- Mock 交互无法覆盖核心流程。
- 发现敏感信息、生成产物或无关大规模重构。

请求修改：

- 行为与任务清单或接口契约不一致。
- 页面只有静态展示，没有真实 Mock 交互。
- 权限只做 UI 隐藏，没有路由或访问边界。
- 回滚路径不可执行。
