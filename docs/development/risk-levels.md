# 风险等级说明

风险等级用于 PR 模板、发布 checklist 和 reviewer 判断。等级越高，需要越强的测试、验收和回滚准备。

## P0：核心安全和访问边界

适用范围：

- 登录、退出、token、认证状态。
- 权限引擎、路由守卫、服务端菜单、按钮权限。
- 请求客户端、全局错误处理、401/403 行为。
- 表单 schema 迁移和运行时渲染安全。

要求：

- 必须有单元测试，覆盖成功、失败和受限路径。
- 必须说明回滚方式。
- 必须验证 `npm run lint:check`、`npm run typecheck`、`npm run test`、`npm run build:prd`。
- Reviewer 至少重点检查权限、安全和错误处理。

## P1：核心业务框架能力

适用范围：

- 标准 CRUD 页面、Pro 组件、字典组件。
- 流程、低代码、大屏、报表、审计等核心模块。
- Mock 数据和接口契约变更。
- 路由、菜单、语言包联动。

要求：

- 必须有 API、Mock、路由或页面测试中与变更对应的部分。
- 必须能在无后端环境下演示核心流程。
- 必须说明回滚方式。
- 页面需要覆盖 loading、空状态、错误态或权限态中受影响的状态。

## P2：文档、配置和交付体验

适用范围：

- 开发文档、部署文档、PR 模板、发布 checklist。
- 非生产默认配置。
- 构建模板、Nginx、Docker 示例。

要求：

- 文档命令必须存在且可执行。
- 配置变更需要说明影响环境。
- 构建或相关文档测试需要通过。
- 回滚方式可以是 Git revert 或恢复配置文件。

## P3：低风险文本和样式调整

适用范围：

- 文案、局部样式、非关键展示信息。
- 不影响接口、权限、认证、构建和部署的调整。

要求：

- 说明影响范围。
- 至少运行与变更相关的最小验证。
- 若触及公共样式或布局，补充截图或页面验证说明。

## 升级规则

满足以下任一条件时，风险等级至少提升一级：

- 影响多个模块或共享组件。
- 修改默认配置、菜单来源或请求前缀。
- 影响生产部署、缓存、运行时配置或 API 网关。
- 无法在本地完全验证，需要后端或运维配合。

## 风险等级判定矩阵

| 变更命中项 | 最低等级 | 必要证据 |
| --- | --- | --- |
| 权限、认证、请求客户端、表单 schema | P0 | 成功、失败、受限路径测试和可执行回滚方式。 |
| CRUD 页面、Pro 组件、流程、低代码、大屏、报表、审计、Mock 契约 | P1 | API、Mock、路由、页面或文档测试覆盖本次改动。 |
| 文档、部署模板、运行时配置、CI、发布流程 | P2 | 命令可执行性、构建或文档测试，以及配置回滚说明。 |
| 文案、局部样式、非关键展示 | P3 | 最小相关验证和影响范围说明。 |

同一 PR 命中多个等级时，从高到低取最高风险等级。比如同时修改文档和请求客户端时，按 P0 审查，而不是按 P2 放行。

## 回滚口径

- 代码变更优先使用 Git revert 回滚。
- 运行时配置通过 `runtime-config.js` 回滚。
- 菜单异常可临时关闭 `menuFromServer`。
- 权限码异常优先下线菜单入口和按钮，再回滚接口行为。
